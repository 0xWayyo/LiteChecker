# LiteChecker

LiteChecker проверяет доступность VLESS/REALITY-подписки с одного или нескольких
устройств и отправляет диагностические отчёты. Версия исходников: `0.6.1`.
Три пакета используют общее ядро и отдельные подписанные каналы обновлений.

## Быстрый старт

Откройте [релизы](https://github.com/0xWayyo/LiteChecker/releases).
Скачайте прикреплённый клиентский ZIP (не архив `Source code`), распакуйте его и
запустите installer для своей ОС:

- macOS arm64/x86_64: `LiteChecker-0.6.1-macOS.zip`, откройте `INSTALL.command` — native DIRECT без Docker;
- Windows 10/11 x64: скачайте `LiteChecker-0.6.1-Windows.zip` и откройте
  `LiteChecker.bat` — нативно, без WSL, Docker и прав администратора;
- Linux x86_64/arm64: `LiteChecker-0.6.1-Linux.zip`, выполните `bash INSTALL.sh`.
  Нужны Docker Engine и Docker Compose; используется обычный маршрут Docker/хоста, режима DIRECT для Linux нет.

Если установлена 0.6.0, выберите «Проверить обновления» в её меню: настройки и ID
сохранятся. Для первой установки используйте новую папку; перенос из тестовых
версий 0.2–0.5 и сброс их каналов не выполняются. Технические архивы `windows-update-source.zip` и
`macos-update-source.zip` предназначены для обновлятора; для первой установки
выбирайте `Windows.zip` или `macOS.zip` соответственно.

На macOS и Linux выберите «Установить и настроить» в меню терминала.
В Windows мастер откроется при первом запуске. Он спросит подписку, токен бота,
ID чата и необязательный прокси. Ввод виден в терминале; укажите ID своего чата.
В Windows уведомления Telegram можно отключить, оставив токен пустым.
После настройки Windows запустите проверки первым пунктом меню.

Первый пункт меню предлагает запуск или остановку по текущему состоянию.
Другие пункты открывают события или последний отчёт, настройки и обновления.
Закрытие меню не останавливает проверки. Повторное открытие файла запуска
не переустанавливает и не перезапускает чекер.

На macOS рядом с `INSTALL.command` находятся `_app` и короткая инструкция.
Для установки и дальнейшего управления открывайте один и тот же `INSTALL.command`.
После успешной установки проверенные файлы внутри `_app` убираются, остаётся
небольшой файл перехода к меню. Не удаляйте `_app` и не отделяйте её от установщика.
Если внутри есть секреты, изменённые или посторонние файлы, уборка пропускается.
Данные и установленная программа остаются в `~/Library/Application Support/LiteChecker`;
точный путь показан в «Настройки → Дополнительно».

В Windows рядом с `LiteChecker.bat` находится `_app`: там код, настройки и отчёты.
Всё управление — через меню. После запуска первый цикл начинается сразу, следующие — каждые 10 минут;
закрытие меню их не останавливает. После перезагрузки Windows запустите мониторинг
вручную. Подписанные обновления проверяются раз в час, пока мониторинг работает,
или вручную из меню. Обновление остановленного чекера не запускает проверки.
[Подробнее о Windows](WINDOWS.md).

Windows DIRECT использует физический интерфейс и Cloudflare DoH, не системный
DNS, который может перехватываться TUN. Если контроль выбранного подключения
не проходит, измерение не переключается на обычный маршрут. Проверена конкретная
конфигурация Happ TUN; обход произвольного VPN или Kill Switch не гарантируется.
Telegram использует отдельный настроенный прокси или обычный маршрут.

Старые установки остаются отдельно. Перед запуском новой остановите старый экземпляр
через его меню, чтобы не запустить две проверки одновременно.

В клиентском ZIP — установщики, необходимый runtime, короткая инструкция и
обновлятор. Тесты, CI, инструменты разработки, подробные руководства и примеры
центрального collector остаются только в исходном репозитории.

## Сборка из checkout

Исходный checkout намеренно не содержит готовых `CONTENTS.sha256.json` и
`update-channel.json`: упаковщик создаёт их для каждой платформы. Следующая
команда собирает исходные платформенные пакеты для проверки и подписания.
Установите [`uv`](https://docs.astral.sh/uv/getting-started/installation/), затем
из корня checkout создайте окружение строго по `uv.lock` и запустите упаковщик:

```bash
uv sync --frozen --no-dev
uv run --frozen --no-dev python scripts/package_platforms.py \
  --version 0.6.1 --repository 0xWayyo/LiteChecker \
  --public-key /absolute/path/signing-public.key --output dist/platform-sources-0.6.1
```

Команда читает только явный список публичных файлов и публичный ключ. Для macOS
и Windows она создаёт технические `update-source.zip`; компактные пользовательские
ZIP с файлом запуска, `_app` и инструкцией собираются на следующем этапе.
Для полной сборки трёх подписанных дистрибутивов используйте
`release.py build-platforms` из [руководства по релизам](docs/development/releases.md).

Центральный collector — опциональный режим. Для него установите extra:

```bash
uv sync --frozen --extra collector
```

Обычные native/standalone/updater команды не требуют FastAPI или uvicorn.
