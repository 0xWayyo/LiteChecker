# LiteChecker

LiteChecker проверяет доступность VLESS/REALITY-подписки с одного или нескольких
устройств и отправляет диагностические отчёты. Версия: `0.5.1` (тестовая).

Windows `0.5.0` снята со стабильного канала. Исправления доступны в тестовой
`0.5.1`; стабильный канал пока остаётся на `0.4.0`.

## Быстрый старт

Для macOS и Linux откройте [стабильный релиз](https://github.com/0xWayyo/LiteChecker/releases/latest).
Для native Windows — [тестовый релиз 0.5.1](https://github.com/0xWayyo/LiteChecker/releases/tag/v0.5.1).
Скачайте прикреплённый клиентский ZIP (не архив `Source code`), распакуйте его и
запустите installer для своей ОС:

- macOS: откройте `INSTALL.command` — native DIRECT работает без Docker;
- Windows 10/11 x64: скачайте `LiteChecker-0.5.1-Windows.zip` и откройте
  `LiteChecker.bat` — нативно, без WSL, Docker и прав администратора;
- Linux: выполните `bash INSTALL.sh`.

Откроется небольшое меню в терминале. При первом запуске выберите «Установить
и настроить»: мастер спросит подписку, токен бота, ID чата и необязательный
прокси. Состояние проверок обновляется автоматически; первый пункт предлагает
действие по текущему состоянию: установку, запуск или остановку. Остальные пункты:
«2 Последние события», «3 Настройки», «4 Проверить обновления» и «0 Закрыть окно».
Пути, состояние обновлений и восстановление находятся в «Настройки → Дополнительно».
Закрытие меню не останавливает проверки. Повторное открытие INSTALL
не переустанавливает и не перезапускает чекер.

На macOS после успешной установки неизменённого публичного пакета рядом остаётся
только `LiteChecker.command` — открывайте его для управления. Проверенные файлы
распаковки удаляются; их можно снова скачать с GitHub. Если в папке есть секреты,
изменённые или посторонние файлы, уборка пропускается. Данные и установленная
программа остаются в `~/Library/Application Support/LiteChecker`; точный путь
показан в «Настройки → Дополнительно».

В Windows рядом с `LiteChecker.bat` находится `_app`: там код, настройки и отчёты.
Всё управление — через меню. Проверки запускаются сразу и каждые 10 минут;
закрытие меню их не останавливает. После перезагрузки Windows запустите мониторинг
вручную. Подписанные обновления проверяются раз в час, пока мониторинг работает,
или вручную из меню. Обновление остановленного чекера не запускает проверки.
[Подробнее о Windows](WINDOWS.md).

Windows DIRECT использует физический интерфейс и Cloudflare DoH, не системный
DNS, который может перехватываться TUN. Если контроль выбранного подключения
не проходит, измерение не переключается на обычный маршрут. Проверена конкретная
конфигурация Happ TUN; обход произвольного VPN или Kill Switch не гарантируется.
Telegram использует отдельный настроенный прокси или обычный маршрут.

Старый WSL-режим остаётся для существующих установок; автоматического переноса
из WSL в native Windows нет. Перед запуском native остановите старый экземпляр.

В клиентском ZIP — установщики, необходимый runtime, короткая инструкция и
обновлятор. Тесты, CI, инструменты разработки, подробные руководства и примеры
центрального collector остаются только в исходном репозитории.

## Сборка из checkout

Исходный checkout намеренно не содержит `CONTENTS.sha256.json`. Разработчику
нужно сначала собрать клиентский архив и запускать installer из распакованной
копии. Установите [`uv`](https://docs.astral.sh/uv/getting-started/installation/),
затем из корня checkout создайте окружение строго по `uv.lock` и запустите
упаковщик через него:

```bash
uv sync --frozen --no-dev
uv run --frozen --no-dev python scripts/package_agent.py
```

Для одного диагностического прогона на macOS откройте `TRY-DIRECT.command`.
Флаг packager `--direct-trial` сохранён как совместимый alias и не создаёт второй
вид архива.

Центральный collector — опциональный режим. Для него установите extra:

```bash
uv sync --frozen --extra collector
```

Обычные native/standalone/updater команды не требуют FastAPI или uvicorn.
