# Пробный прямой режим macOS

Откройте `TRY-DIRECT.command`. Это **один** экспериментальный прогон и один отчёт в настроенную Telegram-группу. Не устанавливает службу и не запускает второй постоянный монитор. Для постоянной проверки каждые 10 минут используйте основной `INSTALL.command`: на macOS он устанавливает native DIRECT без Docker. Инструкция — [INSTALL-AGENT.md](INSTALL-AGENT.md).

При первом запуске автоматически скачиваются закреплённые версии uv и Xray с проверкой SHA-256, Python 3.12.11 и зависимости из `uv.lock`. Docker не нужен. Пароль администратора не запрашивается: проба не меняет VPN, системные маршруты, файрвол или расширения. Закрыть окно можно после отчёта. Для отмены — Ctrl+C.

Если macOS заблокировала скачанный `.command`, разрешите **именно этот файл** через Системные настройки → Конфиденциальность и безопасность → Всё равно открыть. Не отключайте Gatekeeper целиком. Альтернатива для доверенного архива: в Terminal введите `bash `, перетащите `TRY-DIRECT.command` в окно и нажмите Enter.

## Что происходит

- Выбирается единственный активный физический Wi-Fi/Ethernet интерфейс. При неоднозначности проба прекращается.
- Каждое исходящее проверочное TCP-соединение привязывается к его индексу и исходному адресу. Ошибка привязки прерывает соединение; обычного маршрута для проверок нет.
- DNS идёт по TCP к DNS-серверу, полученному по DHCP от этого подключения, через такой же привязанный сокет. Системный DNS и его VPN-настройки не используются.
- HTTP-запросы подписки/IPinfo/контроля, TCP/TLS и внешний транспорт Xray используют этот путь. Внутри проверяемого VLESS-туннеля контрольный HTTPS-запрос идёт как обычно через проверяемый сервер.
- Подписка загружается заново с обходом HTTP-кэша. Если новый валидный список не получен, VPN/SNI-проверки пропускаются; старый снимок не используется. Сам API при этом должен отдавать актуальные данные.
- Если в подписке один адрес повторяется с разными параметрами VLESS/REALITY, проба проверяет каждый вариант отдельно, а не выбирает произвольный. Полные дубликаты объединяются. Поэтому число проверок VPN может превышать число уникальных адресов. Основной парсер обычного режима не меняется.
- Подписка и контроль используют защищённый случайным паролем SOCKS-помощник на `127.0.0.1`. Каждая проверка Xray получает отдельного помощника: ошибки одной конфигурации не влияют на другие, даже если IP совпадают. Все помощники закрываются после проверки и не открыты в локальную сеть.
- Telegram использует отдельный прокси из `secrets/telegram_proxy_url`, если файл есть, иначе обычный маршрут. Это позволяет сообщить в том числе о недоступном прямом выходе. Отказ настроенного прокси не вызывает переход на прямую отправку. Второй запрос IPinfo обычным маршрутом нужен для сравнения IP; это не доказательство доступности серверов.

## Ограничения — важно

**Привязка к Wi-Fi не доказывает отсутствие VPN у провайдера, на роутере или перенаправления системным Network Extension.** Поэтому каждый отчёт помечен «пробный DIRECT» и «Обход VPN не подтверждён». Разные выходные IP — полезный сигнал, но не доказательство маршрута к каждому адресу. Нормальное сообщение «Всё доступно» этот режим не отправляет.

Поддерживается только macOS; Windows/Linux не переключаются автоматически. Ручной/static DNS без DHCP, DNS-сервер без TCP/53, несколько активных физических сетей, отсутствие нужного семейства IP, Kill Switch или политика VPN могут не дать выполнить пробу. В таком случае нет скрытого перехода через VPN и нет автоматического отключения защиты. UDP VPN-протоколы не добавлены; проверяется существующая TCP VLESS/REALITY подписка и TLS сайтов SNI.

Результат UNKNOWN при сбое прямого транспорта не доказывает падение сервера. Город/сеть приблизительно определяются по выходу пробного пути через IPinfo.

### Как читать проблемы

- **Не прошли / DOWN** — зафиксирована неуспешная проверка именно с этого подключения: например, таймаут/отказ TCP, ошибка сертификата или контрольный HTTPS-запрос внутри VLESS не прошёл. Это не утверждение, что сервер недоступен всем или заблокирован провайдером.
- **Не определены / UNKNOWN** — получить надёжный результат не удалось: например, сбой DNS-сервера подключения, ошибка привязки интерфейса, локального Xray или общий лимит времени. Указаны этап и безопасный технический код, если он известен.
- DNS-ошибки не называются ошибками Xray. Один локальный сбой не заменяет причины остальных проверок. Поздний успешный E2E/TLS-ответ остаётся успешным, даже если предыдущая попытка не прошла.

## Данные и повторный запуск

Общий токен и подписка читаются из существующих `secrets/telegram_bot_token` и `secrets/subscription_url`. Группа по умолчанию — та же LiteChecker; переопределение: `LC_TELEGRAM_CHAT_ID`. Docker `.env.standalone` не исполняется и не копируется. Отдельные настройки/ID эксперимента сохраняются в `state/direct-trial`, runtime — в `.native-direct`; **их нельзя передавать другим тестерам**.

Общий прокси Telegram автоматически читается из необязательного `secrets/telegram_proxy_url` (`0600`). Формат: `socks5://LOGIN:PASSWORD@IP:PORT`. Ручное переопределение — `LC_TELEGRAM_PROXY_URL_FILE` или `LC_TELEGRAM_PROXY_URL`; пароль не передавайте в аргументах команды. Прокси применяется только к уведомлениям, не к измерениям и не к определению города. Пустой/нечитаемый/небезопасный файл не игнорируется: исправьте его или удалите настройку, чтобы явно вернуться к обычной доставке.

Последний полученный результат цикла сохраняется **до отправки Telegram** в `state/direct-trial/last-observation.json`: время, выходные IP, все результаты и коды причин. Он не содержит токенов, ссылки подписки или конфигураций VLESS; права файла — `0600`. Следующий результат заменяет предыдущий. Если запуск остановился ещё до цикла, файл может относиться к прошлому запуску — смотрите `report.observed_at`. Это локальная диагностика, не очередь доставки; в архив для других устройств она не включается.

Проба одноразовая, не обещает отложенную доставку после выхода. Успех Telegram печатается только после принятия всех частей сообщения. Для сравнения можно запустить пробу при выключенном и включённом VPN самостоятельно; программа VPN не включает и не выключает.

Для разработчика: `python -m litechecker.direct_check --root . --xray /абсолютный/путь/xray` запускает проверку без отправки Telegram; добавить `--send` для отправки.
