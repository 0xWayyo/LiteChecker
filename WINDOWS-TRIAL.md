# LiteChecker: пробная проверка Windows

Это **ТЕСТОВАЯ СБОРКА**, а не production-обновление и не установщик. Она делает один экспериментальный прогон по явной команде, не создаёт службу и не запускается автоматически.

## Краткая памятка для файла НАЧНИТЕ-ЗДЕСЬ

ТЕСТОВАЯ СБОРКА LiteChecker для Windows 10/11 x64.

1. Распакуйте ZIP полностью в обычную локальную папку. Не запускайте файл прямо из ZIP, сетевой/UNC-папки или ссылки.
2. Сначала откройте `DIAGNOSE-WINDOWS.bat` и дождитесь `windows-state/last-diagnostics.txt`. WSL и права администратора не нужны.
3. Затем откройте `TRY-WINDOWS.bat` и выберите пункт 1. При первом запуске зависимости загрузятся в `.windows-native` рядом с программой; это может использовать текущее VPN-подключение. Сама проверка затем использует отдельный привязанный сетевой путь.
4. Остановить проверку можно через Ctrl+C. Фонового запуска и автозапуска нет.

Локальные настройки и результаты находятся в `windows-state`. Для сравнения запустите отдельные проверки с VPN выключенным и включённым. Если нужно передать результат вручную, передавайте только `last-report.txt` и `last-observation.json`: в них есть публичный IP, имя устройства, примерное местоположение и проверенные цели. Никогда не передавайте `settings.json`, `device.json` или всю папку `windows-state`.

Telegram необязателен и по умолчанию не используется. Настраивайте только собственного бота, чат и при необходимости прокси; отправка выполняется только отдельным пунктом меню.

`DIAGNOSE-WINDOWS.bat` или пункт 6 «Диагностика сети (при проблемах с TUN)» не запрашивает подписку/токен, не использует Xray и сохраняет `windows-state/last-diagnostics.txt`. D2 показывает GUID адаптера, локальные IP-адреса, настроенные адреса DNS, отдельный результат DNS адаптера, bound Cloudflare DoH и фактический внешний IP. Ошибка DNS адаптера остаётся видимой и не заменяется успехом DoH. Для поддержки можно отправить только этот диагностический файл.

Поддерживается один активный подходящий физический Ethernet/Wi-Fi адаптер. Обычный D2-прогон разрешает имена через Cloudflare DoH по HTTPS через строго привязанный Windows backend; системный DNS и DNS адаптера для него не используются. Сети только со scoped/link-local адресами не поддерживаются. WFP, Kill Switch или политика VPN могут заблокировать или перенаправить проверку; гарантии обхода любого TUN нет. Не сбрасывайте сеть и не отключайте защиту ради этого теста.

В этой тестовой сборке на адаптере должен быть настроен хотя бы один DNS-адрес; его ответ не обязателен. Ответы Cloudflare могут отличаться от ответов DNS вашего провайдера — это разные проверки.

## Запуск и меню

Распакуйте архив **целиком**, затем откройте верхний `TRY-WINDOWS.bat`. Путь может содержать пробелы и Unicode. Корень должен быть обычной локальной папкой без reparse point; UNC-пути отклоняются. Поддерживаются Windows 10/11 x64 на процессорах x86-64. Windows ARM, 32-битная Windows и WSL не поддерживаются.

Меню содержит только следующие действия:

- один пробный прогон без Telegram;
- просмотр последнего локального отчёта;
- смена ссылки подписки обычным видимым вводом без запуска проверки;
- необязательная настройка Telegram;
- явный пробный прогон с отправкой отчёта в Telegram;
- диагностика сети без подписки, Telegram и Xray;
- выход.

При первом действии, которому нужен Python, программа скачивает закреплённый uv с GitHub по HTTPS, проверяет SHA-256, устанавливает управляемый Python 3.12.11 и только зависимости строго из `uv.lock`. Для проверки подписки дополнительно скачивается проверенный по SHA-256 Xray; диагностике он не нужен. Локальный проект не собирается и не устанавливается: изолированный Python запускает абсолютный `scripts/windows-entry.py`, который подключает исходники только из распакованной `_app/src`. Поэтому отдельные build-зависимости не скачиваются. Всё остаётся в `.windows-native` внутри распакованной папки. Глобальный Python, `PYTHONPATH`, PATH, реестр, execution policy, маршруты, DNS, VPN, firewall и службы не меняются. Параметр обхода execution policy применяется только к одному процессу Windows PowerShell, запущенному `.bat`.

Загрузка зависимостей идёт обычным текущим сетевым путём и может пройти через включённый VPN. Это не результат измерения. Измерения D2 запускаются после подготовки и используют отдельный Python-механизм привязки к выбранному физическому адаптеру. Разрешение имён обычного прогона выполняется через Cloudflare DoH по HTTPS через тот же строго bound Windows backend, а не через системный DNS или DNS адаптера. Перед VLESS/TLS-проверками сохраняется прежний preflight exit-gate: если контроль фактического выхода не подтверждён, прогон останавливается, а не переходит на обычный маршрут. Даже успешные DoH, exit-gate и привязка не доказывают обход всех TUN, VPN, WFP-фильтров, сетевых расширений или VPN на роутере.

## Настройки, результаты и Telegram

При первой проверке ссылка подписки запрашивается обычным видимым вводом. Так же вводятся токен и прокси Telegram. Сохранённые значения программа повторно не показывает. Настройки сохраняются локально в `windows-state/settings.json`. Рядом создаётся локальная идентичность устройства. В окружении нет резервных значений для подписки или Telegram.

По умолчанию проверка ничего не отправляет. Для Telegram укажите только реквизиты собственного бота и чата. Необязательный SOCKS5-прокси относится только к отправке Telegram, а не к измерениям. Пункт отправки запускает один новый пробный прогон и отправляет его отчёт явно; постоянной доставки и очереди нет.

После успешного прогона программа сохраняет:

- `windows-state/last-report.txt` — читаемый последний отчёт;
- `windows-state/last-observation.json` — структурированный последний результат;
- `windows-state/settings.json` и `windows-state/device.json` — приватные локальные настройки и идентичность.

В отчётах могут быть публичные IP-адреса, имя устройства, приблизительные город/провайдер и адреса проверенных целей. Для ручной передачи используйте только `last-report.txt` и `last-observation.json`. Никогда не пересылайте `settings.json`, `device.json` или всю папку `windows-state`: там находятся ссылка подписки и, если настроено, реквизиты Telegram.

## Отдельная диагностика сети

Если основная проверка останавливается до TUN/VLESS-измерений, используйте пункт 6 меню или верхний `DIAGNOSE-WINDOWS.bat`. Диагностика подготавливает только закреплённый uv, управляемый Python 3.12.11 и зависимости из `uv.lock`. Она не скачивает и не запускает Xray, не читает и не создаёт настройки подписки/Telegram и не отправляет результат.

Результат сохраняется в `windows-state/last-diagnostics.txt`. Он содержит GUID выбранного адаптера, локальные IP-адреса, настроенные адреса DNS, отдельные результаты DNS адаптера и Cloudflare DoH, фактический внешний IP, этапы проверки и числовые ошибки Windows. В нём нет ссылки подписки или Telegram-токена. Для поддержки отправляйте только `last-diagnostics.txt`, а не всю папку `windows-state`.

Диагностика D2 отдельно проверяет привязку сокета и исходный DNS адаптера; отсутствие DNS, ошибка TCP/53 или ответа остаётся самостоятельной ошибкой и не скрывается последующим успехом. Отдельно проверяется Cloudflare DoH по HTTPS через строго bound Windows backend, после чего через этот же путь запрашивается IPinfo и записывается фактически наблюдаемый внешний IP. Независимый TCP/TLS-контроль Cloudflare (`1.1.1.1`, для IPv6-only — `2606:4700:4700::1111`) не требует DNS и также использует выбранный адаптер. Эти этапы не заменяют проверку подписки и не доказывают обход любого TUN. Это новый прогон: успешный этап не объясняет предыдущий сбой. При повторном запуске файл диагностики заменяется — сохраните копию для сравнения.

Это ограниченная диагностика только для чтения: она не устанавливает службу, не меняет адаптер, маршруты, DNS, VPN, firewall или системные настройки и не исправляет сеть автоматически.

## Как сравнить VPN выключен/включён

1. Выключите VPN обычным способом в его приложении, запустите `DIAGNOSE-WINDOWS.bat`, затем выполните пункт 1 в `TRY-WINDOWS.bat` без Telegram.
2. Сохраните копии `last-report.txt` и `last-observation.json` под понятными именами.
3. Включите VPN обычным способом и повторите ту же последовательность: диагностика, затем пункт 1.
4. Сравните фактические внешние IP из диагностики, выходные IP и статусы обычных прогонов. Различие полезно для диагностики, но не является доказательством обхода VPN/TUN для каждой цели.

Программа сама не включает и не выключает VPN. Не сбрасывайте сетевые настройки, не отключайте firewall, Kill Switch или защитное ПО ради проверки.

## Ограничения тестовой сборки

- Только Windows 10/11 x64; ARM, 32-bit и WSL отклоняются.
- Должен быть ровно один активный подходящий физический Ethernet/Wi-Fi адаптер. Неоднозначность завершает проверку без фонового fallback.
- Нужен пригодный исходный адрес. Обычный D2-прогон использует bound Cloudflare DoH; DNS адаптера проверяется только как отдельный диагностический сигнал, и его ошибка явно остаётся в `last-diagnostics.txt`. Scoped/link-local-only сети не поддерживаются.
- WFP, Kill Switch, защитное ПО, политика маршрутизации, VPN на роутере и другие перехваты могут блокировать или перенаправлять трафик.
- Результат описывает наблюдение одного прогона. Он не сертифицирует доступность сервиса для всех и не гарантирует обход VPN или блокировок.
- Ctrl+C останавливает текущий прогон. Автозапуска, службы, драйвера и production-обновления в этом пакете нет.
