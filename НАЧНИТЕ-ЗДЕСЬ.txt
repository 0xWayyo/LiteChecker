LiteChecker — установка

1. Распакуйте архив целиком. Не запускайте файлы прямо из ZIP.
2. Откройте файл для вашей системы:
   macOS   → INSTALL.command
   Windows → INSTALL.bat
   Linux   → INSTALL.sh (или команда bash INSTALL.sh в этой папке)
3. Следуйте подсказкам. В готовом PRIVATE-архиве ничего вводить не нужно.

Имя компьютера, ОС, город и сеть определяются автоматически. Город берётся
из IPinfo и помечается «по IP» — это геолокация выхода в интернет, а не GPS.
У каждого устройства свой постоянный ID; в одном городе может быть много тестеров.

На macOS Docker НЕ нужен: INSTALL.command устанавливает постоянный DIRECT.
Программа хранится в ~/Library/Application Support/LiteChecker и работает
через launchd. Первый цикл сразу, далее каждые 10 минут, без пересечения.
После перезагрузки запуск возобновляется при входе пользователя в macOS.
DNS и проверки идут через выбранный физический интерфейс; если это невозможно,
будет «не проверено», а не скрытый переход через VPN.

На Windows/Linux нужен установленный и запущенный Docker. Если его нет,
установщик покажет инструкцию. На Windows также нужны WSL2 + Ubuntu
и интеграция Ubuntu в Docker Desktop. Первая подготовка Windows может
потребовать перезагрузки; Windows-вариант не проверен на реальной машине.

Первый запуск скачивает компоненты. После запуска проверки работают в фоне,
первый настоящий отчёт появится в Telegram. Компьютер не должен уходить в сон.

ВАЖНО: LiteChecker-READY-PRIVATE.zip содержит общий токен бота, подписку
и общий Telegram-прокси, если он настроен. Через прокси идут только уведомления.
Передавайте этот архив только доверенным тестерам. Это НЕ зашифрованный архив.
Не публикуйте его и не отправляйте посторонним.

Не переносите папку state, runtime, native-settings.json и .env.standalone между компьютерами.
На том же компьютере их нужно сохранять при обновлении.

macOS: настройки — native-settings.json в постоянной папке установки.
Windows/Linux: настройки — .env.standalone. LC_AGENT_NAME задаёт своё имя;
пустое значение означает автоматическое. После изменения перезапустите службу.

Город и сеть определяются через IPinfo. Сервис видит внешний
IP, но не получает имя компьютера, токен или подписку. На macOS DIRECT город
относится к выходу физических проверок; при недоступном контроле выхода цикл
не выполняется. В обычном Docker-режиме IP может относиться к VPN-серверу.
Привязка к интерфейсу не гарантирует обход VPN на роутере или Kill Switch.
TRY-DIRECT.command — отдельная разовая проба, не основной установщик.
Остановить: bash run.sh stop. Посмотреть журнал: bash run.sh logs.
Подробная инструкция и дополнительные настройки:
https://github.com/0xWayyo/LiteChecker/blob/main/docs/installation/agent.md

Обновления программы: если в пакете настроен update-channel.json,
установщик подключит проверку подписанных версий раз в час.
Сохраняются текущая и одна предыдущая управляемая версия; старые временные
загрузки очищаются. Секреты, ID, настройки и очередь отчётов сохраняются.
Без канала обновлений статус будет unconfigured, автоматических загрузок нет.
Подробнее и команды управления: docs/operations/updates.md.
