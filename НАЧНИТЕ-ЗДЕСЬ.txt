LiteChecker — начните здесь

1. Распакуйте ZIP целиком. Не запускайте файлы прямо из архива.
2. Откройте файл вашей системы:
   macOS   — INSTALL.command
   Windows — LiteChecker.bat (из LiteChecker-Windows-0.5.0.zip)
   Linux   — bash INSTALL.sh
3. В меню выберите «Установить и настроить».

Мастер попросит URL подписки, токен Telegram-бота, ID чата и необязательный
прокси для уведомлений. Всё, что вы вводите, видно в окне терминала.
ID группы обычно начинается с минуса. Данные бота не входят в публичный ZIP.
Готовые настройки PRIVATE-пакета сохраняются; заново вводить их не нужно.

ПОСЛЕ УСТАНОВКИ

Состояние проверок в меню обновляется автоматически. Первый пункт предлагает
действие по текущему состоянию: установку, запуск или остановку.
Остальные пункты: 2 Последние события, 3 Настройки,
4 Проверить обновления, 0 Закрыть окно.
Пути, состояние обновлений и восстановление: «Настройки → Дополнительно».
Закрытие окна не останавливает проверки. Чтобы остановить их, выберите
«Остановить». После изменения настроек нужно отдельно выбрать «Запустить».
Проверки идут каждые 10 минут. Компьютер должен быть включён и не спать.

На Mac открывайте LiteChecker.command, оставшийся в распакованной папке.
Его можно перенести на рабочий стол. Неизменённые публичные файлы установки
убираются после успешной установки; снова скачать их можно с GitHub.
Если рядом есть секреты, ваши файлы или правки, удаление пропускается.
В этом случае для управления можно также повторно открыть INSTALL.command.

Программа и данные на Mac: ~/Library/Application Support/LiteChecker.
Это постоянная папка для обновлений: ID устройства, настройки и очередь
отчётов не зависят от скачанного ZIP. Точный путь: «Настройки → Дополнительно».
Docker на Mac не нужен. Фоновый запуск возобновляется при входе в macOS.
Привязка DIRECT к интерфейсу не гарантирует обход VPN на роутере или Kill Switch.

В Windows 10/11 x64 откройте LiteChecker.bat. Рядом находится _app — код и данные.
WSL, Docker и права администратора не нужны. Закрытие меню не останавливает
мониторинг; для остановки выберите первый пункт. После перезагрузки Windows
запустите мониторинг вручную. Автозапуск Windows не добавляется.
Старый экземпляр WSL перед этим остановите, чтобы не получать дубли отчётов.
Linux использует распакованную папку и Docker/Compose: не удаляйте её.

ОБНОВЛЕНИЯ

«4 Проверить обновления» в меню запрашивает подписанный релиз
сразу, не дожидаясь очередной часовой проверки (в Windows — пока мониторинг работает). Если версия новее и
проходит проверку, она устанавливается. Результат появится в меню.
Нужны доступ к GitHub и включённый канал обновлений.
Настройки, секреты, ID и очередь отчётов сохраняются. Остаются текущая
и одна предыдущая управляемая версия; старые временные загрузки очищаются.

ВАЖНО

Имя, ОС, город и сеть определяются автоматически; город через IPinfo —
это геолокация выхода в интернет, не GPS. IPinfo видит внешний IP, но
не получает имя компьютера, токен бота или подписку. В обычном Docker-режиме
город может относиться к VPN; в native DIRECT — к выходу физических проверок.

PRIVATE-архив содержит общий токен, подписку и настроенный прокси.
Передавайте его только доверенным тестерам. Это не зашифрованный архив.
Не переносите state, runtime и настройки устройства на другие компьютеры.
Для уведомлений используется заданный Telegram-прокси; проверки через него не идут.
