# LiteChecker: установка и управление

Каждое устройство само обновляет подписку, проверяет VPN-адреса и SNI и отправляет отчёт прямо в настроенный Telegram-чат. В Windows уведомления можно отключить. Общий collector, домен и регистрация устройств не нужны.

Подписку, Telegram-токен и ID чата задайте на каждом устройстве. Для отчётов в одну группу можно использовать общего бота и чат. У каждого устройства — собственный постоянный ID; имя компьютера, ОС, город и сеть определяются автоматически. Один город может быть у любого числа агентов.

## Самый простой запуск

Скачайте клиентский ZIP версии 0.6.1 из [релизов](https://github.com/0xWayyo/LiteChecker/releases), распакуйте его целиком в новую папку и запустите файл своей ОС:

- [macOS](../../MACOS.md): `LiteChecker-0.6.1-macOS.zip` → `INSTALL.command`, native DIRECT для Apple Silicon и Intel.
- [Windows](../../WINDOWS.md): `LiteChecker-0.6.1-Windows.zip` → `LiteChecker.bat`, native DIRECT для Windows 10/11 x64.
- [Linux](../../LINUX.md): `LiteChecker-0.6.1-Linux.zip` → `bash INSTALL.sh`, Docker Engine и Compose для x86_64/arm64.

На macOS и Linux выберите «Установить и настроить». В Windows мастер откроется при первом запуске. Введите HTTPS-ссылку подписки, токен бота, ID своего чата и необязательный прокси Telegram. Ввод виден в терминале. На Windows токен можно оставить пустым, чтобы работать без уведомлений; после настройки отдельно выберите «Запустить проверки».

В macOS и Windows рядом с файлом запуска находятся `_app` и короткая инструкция. Сохраняйте их вместе. Python и Xray устанавливаются автоматически; Docker для этих платформ не нужен. Первая подготовка скачивает зависимости и требует интернета. Повторное открытие меню сохраняет настройки и ID и само по себе не запускает проверки.

С версии 0.6.0 обновляйтесь через пункт «Проверить обновления»: настройки и ID сохраняются. Для перехода с тестовых версий 0.2–0.5 нужна отдельная установка: их данные не переносятся, старый канал не сбрасывается. Перед запуском новой копии остановите старую через её меню. Технические ZIP с `update-source` в имени предназначены для обновлятора.

## macOS: основной режим DIRECT

После установки программа находится в `~/Library/Application Support/LiteChecker`, а служба `com.litechecker.direct` работает через пользовательский launchd. Для управления открывайте тот же `INSTALL.command`. После успешной установки проверенные файлы внутри `_app` убираются, остаётся переход к постоянной программе; не удаляйте `_app`. Окно меню можно закрыть. После перезагрузки служба возобновляется при входе пользователя; компьютер должен быть включён и не спать.

Первый цикл начинается сразу, следующие — каждые 600 секунд от начала цикла, без пересечения и без серии догоняющих запусков после сна. Перед каждым циклом заново определяются физический интерфейс и DHCP DNS, загружается подписка с обходом HTTP-кэша. Проверяются все поддержанные варианты VPN и SNI только из этого ответа; удалённые адреса исключаются сразу. Если получить валидную непустую подписку не удалось, проверки пропускаются, а отчёт сообщает об ошибке обновления — сохранённый список не используется. DNS и внешний транспорт Xray идут через привязанные к интерфейсу соединения; обычный VPN-маршрут не используется как запасной.

Telegram использует свой прокси, если он настроен, иначе обычный маршрут. Очередь сохраняется до подтверждения Telegram и повторяется при временных ошибках и после перезапуска. Старые сообщения помечены «Отложенная доставка» и содержат исходное время наблюдения; они не означают новую проверку. После аварии на границе отправки/подтверждения часть сообщения может прийти повторно.

Актуальность ограничена ответом API на начало цикла. Если сам API продолжает отдавать удалённые адреса, они останутся в проверке до изменения его ответа. Запрос включает случайный query-параметр: подписанные URL, запрещающие дополнительные параметры, могут быть несовместимы; запасного запроса без защиты от кэша нет.

Очередь ограничена 32 сообщениями и 256 ожидающими частями. При переполнении удаляются старые сообщения целиком, а число пропусков сохраняется в `state/native-direct/status.json` (`telegram.dropped_messages`, ошибка `outbox-overflow`). Это ограничение доставки, не признак отказа серверов. Доставка накопившейся очереди ограничена по времени, чтобы новые проверки не ждали её часами.

Дополнительные команды из постоянной папки программы:

```bash
bash run.sh status
bash run.sh logs
bash run.sh stop
bash run.sh start
```

Разовая проверка: `bash run.sh check` при остановленной службе.

Обновление через меню сохраняет `native-settings.json` (настройки как JSON, не shell), `secrets/` и `state/native-direct/`. Если стандартная папка занята старой несовместимой установкой, укажите отдельную пустую папку через `LITECHECKER_NATIVE_ROOT` при запуске установщика; старые данные автоматически не удаляются.

Город и сеть в DIRECT-отчёте берутся именно с выхода физических проверок; обычный выход IPinfo служит только для сравнения. При отсутствии надёжного контроля выхода цикл помечается непроверенным. VPN на роутере, Kill Switch, системные сетевые фильтры, DHCP DNS без TCP/53 или несколько активных физических сетей могут помешать проверкам. Автоматического отключения защиты VPN и обещания универсального обхода нет.

## Windows: native DIRECT

Для установки и управления открывайте `LiteChecker.bat`. WSL, Docker и права администратора не требуются. Мастер сохраняет настройки в `_app/windows-state`; сохранённые токены и ссылки повторно не показываются. Пустой ввод оставляет сохранённое значение, минус (`-`) удаляет сохранённый Telegram-прокси. Ctrl+C отменяет настройку без частичной записи.

После команды запуска первый цикл начинается сразу, следующие — каждые 10 минут. Закрытие меню не останавливает мониторинг; после перезагрузки Windows запустите его вручную. Автозапуск Windows не добавляется. Подписанные обновления проверяются раз в час, пока мониторинг работает, и вручную через меню. Обновление остановленного чекера не запускает проверки.

DIRECT использует физический интерфейс и Cloudflare DoH вместо системного DNS. Если контроль выбранного подключения не проходит, измерение не переключается на обычный маршрут. Обход произвольного VPN или Kill Switch не гарантируется. Telegram использует отдельный настроенный прокси или обычный маршрут.

В меню доступны последний отчёт и диагностика сети. Для поддержки передавайте только `last-report.txt` или `last-diagnostics.txt`; всю папку `_app/windows-state` пересылать не нужно.

## Что передавать

Передавайте публичный клиентский ZIP для нужной ОС. Подписку и данные Telegram вводите отдельно на каждом устройстве через мастер; не добавляйте их в архив программы.

Не передавайте `state/`, `windows-state/`, `.env.standalone`, `native-settings.json`, `secrets/` и runtime от уже работающего устройства. Новый ID и локальное состояние создаются автоматически при первом запуске. На том же компьютере локальное состояние сохраняется при обновлении.

Токен даёт управление ботом, а ссылка — доступ к подписке. Делитесь ими только с доверенными тестерами; не публикуйте их в Git или общем архиве.

## Linux: Docker

Этот раздел относится к Linux standalone в Docker. При включённом стороннем VPN Docker может проверять через VPN и получать Fake-IP от его DNS. Такой отчёт не является измерением местного провайдера; DIRECT для Linux не реализован.

1. Установите [Docker Engine + Compose plugin](https://docs.docker.com/engine/install/). Команда `docker info` должна работать от вашего пользователя без sudo.
2. Распакуйте Linux ZIP в постоянную папку, откройте в ней терминал.
3. Выполните `bash INSTALL.sh`, выберите установку и заполните мастер. Введите ID своего чата (`REPLACE_WITH_TELEGRAM_CHAT_ID`), а не значение другого устройства.

Установщик собирает образ под архитектуру компьютера и запускает проверки. Для отдельной проверки после установки сначала остановите фоновый экземпляр:

```bash
bash run.sh stop
bash run.sh check
bash run.sh start
```

`check` делает одну настоящую проверку. Код завершения 0 означает подтверждение отправки текущего отчёта Telegram API; проверьте сообщение в группе. Если ошибка — не переходите к `start`, пока не исправите её. Запускайте `check` только при остановленном фоновом экземпляре.

`start` запускает проверку в фоне и настраивает перезапуск контейнера. Python и Xray отдельно ставить не требуется. Первая сборка скачивает зависимости, поэтому требует интернета. Следующий цикл начинается через 10 минут после окончания предыдущего; сама проверка тоже занимает время.

### Управление Linux

```bash
bash run.sh status  # состояние контейнера
bash run.sh logs    # последние события и дальнейшие логи; Ctrl+C только закрывает просмотр
bash run.sh stop    # остановить проверки
bash run.sh start   # запустить / применить обновлённый код или настройки
```

Город и название можно изменить в `.env.standalone`, затем выполнить `bash run.sh start`. ID не меняйте: он хранится в `state/standalone/device.json`. Дополнительный `LC_AGENT_ID` можно задать вручную только до первого запуска, например `moscow-ivan-home`.

Для обновлений используйте меню `bash INSTALL.sh`: `.env.standalone`, `secrets/` и `state/` сохраняются. На другой компьютер переносите чистый архив, а не рабочую папку целиком.

## Автоматическое название и сеть

Имя компьютера и ОС берутся на хосте, поэтому имя Docker-контейнера не выдаётся за имя устройства. Настоящее имя человека, SSID Wi-Fi, серийный номер и MAC-адрес программа не собирает. Пустое `LC_AGENT_NAME` в настройках macOS/Linux включает автоматическое имя. При переименовании компьютера на Linux повторно откройте настройки и перезапустите проверки; ID останется тем же.

Город и сеть определяются через **IPinfo** по HTTPS перед каждым циклом, одним общим запросом. IPinfo видит внешний IP; токен, подписка, имя компьютера и результаты проверок не передаются. Город отмечается `(по IP)`; при ошибке показывается «Город не определён», а не выдуманная или устаревшая локация. Данные описывают выход в интернет, а не точное местонахождение человека: при VPN могут относиться к VPN/хостингу.

Используется публичный `https://ipinfo.io/json` без отдельного API-ключа. При нескольких устройствах за одним NAT они используют общий внешний IP и могут совместно исчерпать лимит сервиса. Отказ/лимит сервиса не останавливает VPN-проверки. [Условия публичного API IPinfo](https://support.ipinfo.io/hc/en-us/articles/30792479436562-What-Is-the-Difference-Between-Using-the-Authenticated-Free-Plan-and-the-Public-API-With-No-Account).

При успехе подпись дополняется `· сеть по IP: …`. При ошибке/лимите/таймауте имя остаётся без сети; прошлый провайдер не подставляется. Запрос ограничен тремя секундами. На macOS/Linux ручное `LC_AGENT_CITY` переопределяет город, ручное `LC_AGENT_NAME` — имя и по умолчанию отключает добавление сети. Полностью отключить IPinfo можно двумя настройками: `LC_AUTO_CITY='false'` и `LC_AUTO_NETWORK='false'`. После изменения настроек перезапустите проверки; ID сохранится.

## Важно для честных результатов

- Устройство должно оставаться включённым; сон приостанавливает проверки. На Linux также должен работать Docker, на Windows мониторинг после перезагрузки запускается вручную.
- В Docker системный VPN может менять точку измерения. На macOS/Windows DIRECT привязывает проверки к физическому интерфейсу, но не гарантирует обход любого VPN или Kill Switch.
- «Всё доступно» приходит только при полном успешном свежем цикле. При проблемах перечисляются только сбои; время наблюдения и устройство указаны в отчёте.
- Очередь Telegram сохраняется на диске, временные сбои повторяются. После исправления токена/прав бота перезапустите проверки; недоставленные сообщения повторятся. Ёмкость очереди и число повторов ограничены, старые отчёты не выдаются за новые.
- Если компьютер выключен или полностью потерял интернет, он не может прислать уведомление о собственном отключении. Для отдельного контроля пропавших устройств нужен [центральный режим](../operations/full-reference.md).
- Программа использует `sendMessage`, не запускает конкурирующий опрос `getUpdates`. [Telegram Bot API](https://core.telegram.org/bots/api#sendmessage).
