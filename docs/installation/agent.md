# LiteChecker: установка у нового тестера

Каждое устройство само обновляет подписку, проверяет VPN-адреса и SNI и отправляет отчёт прямо в Telegram. Общий collector, домен и регистрация устройств не нужны.

У всех тестеров одинаковые Telegram-токен, ID чата и URL подписки. У каждого устройства — собственный постоянный ID; имя компьютера, ОС, город и сеть собираются автоматически. Один город может быть у любого числа агентов.

## Самый простой запуск

Распакуйте архив целиком. Откройте `INSTALL.command` на macOS, `INSTALL.bat` на Windows или запустите `bash INSTALL.sh` на Linux. На macOS устанавливается фоновый **native DIRECT без Docker**. На Windows/Linux установщик проверяет Docker и объясняет, каких компонентов не хватает.

В готовом **LiteChecker-READY-PRIVATE.zip** общие токен, подписка и необязательный Telegram-прокси уже заполнены: ничего вводить не нужно. Имя будет вида `Ivan-MacBook (macOS)`, город и сеть добавятся из IPinfo. Повторный запуск установщика сохраняет настройки и ID. Первая подготовка скачивает зависимости и требует интернета.

## macOS: основной режим DIRECT

После `INSTALL.command` программа находится в `~/Library/Application Support/LiteChecker`, а служба `com.litechecker.direct` работает через пользовательский launchd. Окно установщика можно закрыть. После перезагрузки служба возобновляется при входе пользователя; компьютер должен быть включён и не спать.

Первый цикл начинается сразу, следующие — каждые 600 секунд от начала цикла, без пересечения и без серии догоняющих запусков после сна. Перед каждым циклом заново определяются физический интерфейс и DHCP DNS, загружается подписка с обходом HTTP-кэша. Проверяются все поддержанные варианты VPN и SNI только из этого ответа; удалённые адреса исключаются сразу. Если получить валидную непустую подписку не удалось, проверки пропускаются, а отчёт сообщает об ошибке обновления — сохранённый список не используется. DNS и внешний транспорт Xray идут через привязанные к интерфейсу соединения; обычный VPN-маршрут не используется как запасной.

Telegram использует только свой прокси, если он настроен. Очередь сохраняется до подтверждения Telegram и повторяется при временных ошибках и после перезапуска. Старые сообщения помечены «Отложенная доставка» и содержат исходное время наблюдения; они не означают новую проверку. После аварии на границе отправки/подтверждения часть сообщения может прийти повторно.

Актуальность ограничена ответом API на начало цикла. Если сам API продолжает отдавать удалённые адреса, они останутся в проверке до изменения его ответа. Запрос включает случайный query-параметр: подписанные URL, запрещающие дополнительные параметры, могут быть несовместимы; запасного запроса без защиты от кэша нет.

Очередь ограничена 32 сообщениями и 256 ожидающими частями. При переполнении удаляются старые сообщения целиком, а число пропусков сохраняется в `state/native-direct/status.json` (`telegram.dropped_messages`, ошибка `outbox-overflow`). Это ограничение доставки, не признак отказа серверов. Доставка накопившейся очереди ограничена по времени, чтобы новые проверки не ждали её часами.

Из распакованной или постоянной папки программы:

```bash
bash run.sh status
bash run.sh logs
bash run.sh stop
bash run.sh start
```

Разовая проверка: `bash run.sh check` при остановленной службе. `TRY-DIRECT.command` остаётся независимой пробой с отдельным ID/состоянием и пометкой «пробный».

Обновление: распакуйте новый архив и снова запустите `INSTALL.command`. Постоянные данные сохраняются: `native-settings.json` (настройки как JSON, не shell), `secrets/`, `state/native-direct/`. Первый переход с Docker переносит локальный ID из `state/standalone/device.json`, если он есть; существующий ID постоянной установки не заменяется. Исходная папка и старое состояние не удаляются.

Город и сеть в DIRECT-отчёте берутся именно с выхода физических проверок; обычный выход IPinfo служит только для сравнения. При отсутствии надёжного контроля выхода цикл помечается непроверенным. VPN на роутере, Kill Switch, системные сетевые фильтры, DHCP DNS без TCP/53 или несколько активных физических сетей могут помешать проверкам. Автоматического отключения защиты VPN и обещания универсального обхода нет.

На Windows нужны WSL2, Ubuntu и интеграция Ubuntu в Docker Desktop. Установщик переносит только программу и общие секреты в домашнюю папку Ubuntu (`~/LiteChecker`), не копирует чужой ID и сохраняет местные настройки. При отсутствующих компонентах он показывает подсказки; возможна перезагрузка Windows. Нативного Windows-запуска без WSL2 нет.

## Что передавать

Для своих доверенных тестеров передайте **LiteChecker-READY-PRIVATE.zip** — в нём есть токен, URL подписки и общий прокси, если настроен, но нет личного ID, базы, runtime и состояния устройства. Архив не зашифрован: не публикуйте его. Для варианта без секретов используйте **LiteChecker-agent.zip** и отдельно подготовьте `secrets/telegram_bot_token`, `secrets/subscription_url` и при необходимости `secrets/telegram_proxy_url` (права `0600`).

Не передавайте `state/`, `.env.standalone`, `native-settings.json` и runtime от уже работающего устройства. Новый ID и локальный ключ создаются автоматически при первом запуске. На том же компьютере локальное состояние нужно сохранять при обновлении.

Токен даёт управление ботом, а ссылка — доступ к подписке. Делитесь ими только с доверенными тестерами; не публикуйте их в Git или общем архиве.

## Windows/Linux: ручная установка Docker-режима

Оставшиеся инструкции в этом разделе относятся к обычному Docker/collector-режиму, **не к macOS native DIRECT**. При включённом стороннем VPN Docker может проверять через VPN и получать Fake-IP от его DNS. Такой отчёт не является измерением местного провайдера; автоматический DIRECT для Windows/Linux пока не реализован.

1. Установите Docker:
   - Linux: [Docker Engine + Compose plugin](https://docs.docker.com/engine/install/).
   - Windows: [Docker Desktop с WSL2](https://docs.docker.com/desktop/features/wsl/) и Ubuntu. Включите интеграцию с Ubuntu; команды выполняйте в её терминале. Распакуйте проект в домашний каталог Ubuntu, не в `/mnt/c`, чтобы работали Linux-права файлов.
2. Распакуйте архив, откройте терминал в папке `LiteChecker`.
3. Выполните:

```bash
bash run.sh setup
bash run.sh check
bash run.sh start
```

`setup` предложит необязательные город и название, ID чата, общий Telegram-токен и URL подписки. Пустое название (Enter) включает имя компьютера + ОС, пустой город — геолокацию IPinfo. Для нашей группы ID по умолчанию **-5361201677**: просто нажмите Enter. Ввод токена и подписки скрыт. Если два secret-файла уже переданы, повторно вводить их не потребуется. `setup --quick`, который использует файл INSTALL, ничего не спрашивает при заполненных общих секретах.

Пример названий: «Иван / домашний ПК / Ростелеком», «Алексей / ноутбук / МТС». Это подпись отчёта; уникальность обеспечивает автоматически созданный ID, а не название города.

`check` собирает образ под архитектуру этого компьютера и делает одну настоящую проверку. Код завершения 0 означает подтверждение отправки текущего отчёта Telegram API; проверьте сообщение в группе. Если ошибка — не переходите к `start`, пока не исправите её. Запускайте `check` только при остановленном фоновом экземпляре.

`start` запускает проверку в фоне и настраивает перезапуск контейнера. Python и Xray отдельно ставить не требуется. Первая сборка скачивает зависимости, поэтому требует интернета. Следующий цикл начинается через 10 минут после окончания предыдущего; сама проверка тоже занимает время.

## Управление

```bash
bash run.sh status  # состояние контейнера
bash run.sh logs    # последние события и дальнейшие логи; Ctrl+C только закрывает просмотр
bash run.sh stop    # остановить проверки
bash run.sh start   # запустить / применить обновлённый код или настройки
```

Город и название можно изменить в `.env.standalone`, затем выполнить `bash run.sh start`. ID не меняйте: он хранится в `state/standalone/device.json`. Дополнительный `LC_AGENT_ID` можно задать вручную только до первого запуска, например `moscow-ivan-home`.

При обновлении заменяйте файлы программы из нового архива, сохраняя `.env.standalone`, `secrets/` и `state/`, затем выполните `bash run.sh start`. Повторный `setup` намеренно не перезаписывает существующие настройки. На другой компьютер переносите чистый архив, а не рабочую папку целиком.

## Автоматическое название и сеть

Пустое `LC_AGENT_NAME` включает автоматическое имя. Имя компьютера и ОС берутся запускателем на хосте, поэтому имя Docker-контейнера не выдаётся за имя устройства. Настоящее имя человека, SSID Wi-Fi, серийный номер и MAC-адрес программа не собирает. При переименовании компьютера запустите установщик ещё раз: подпись изменится, ID останется тем же.

Город и сеть определяются через **IPinfo** по HTTPS перед каждым циклом, одним общим запросом. IPinfo видит внешний IP; токен, подписка, имя компьютера и результаты проверок не передаются. Город отмечается `(по IP)`; при ошибке показывается «Город не определён», а не выдуманная или устаревшая локация. Данные описывают выход в интернет, а не точное местонахождение человека: при VPN могут относиться к VPN/хостингу.

Используется публичный `https://ipinfo.io/json` без отдельного API-ключа. Его лимит — 1000 запросов в сутки на общий внешний IP; один агент при стандартном интервале делает не более примерно 144 запросов в сутки. При нескольких агентах за одним NAT лимит общий. Отказ/лимит сервиса не останавливает VPN-проверки. [Условия публичного API IPinfo](https://support.ipinfo.io/hc/en-us/articles/30792479436562-What-Is-the-Difference-Between-Using-the-Authenticated-Free-Plan-and-the-Public-API-With-No-Account).

При успехе подпись дополняется `· сеть по IP: …`. При ошибке/лимите/таймауте имя остаётся без сети; прошлый провайдер не подставляется. Запрос ограничен тремя секундами. Ручное `LC_AGENT_CITY` переопределяет город, ручное `LC_AGENT_NAME` — имя и по умолчанию отключает добавление сети. Полностью отключить IPinfo можно двумя настройками: `LC_AUTO_CITY='false'` и `LC_AUTO_NETWORK='false'`. После изменения настроек снова запустите установщик; ID сохранится.

## Важно для честных результатов

- Устройство и Docker должны оставаться включёнными; сон приостанавливает проверки. Включите автозапуск Docker после перезагрузки.
- Системный VPN меняет точку измерения. Чтобы проверять местного провайдера, используйте прямой выход через нужную сеть.
- «Всё доступно» приходит только при полном успешном свежем цикле. При проблемах перечисляются только сбои; время наблюдения и устройство указаны в отчёте.
- Очередь Telegram сохраняется на диске, временные сбои повторяются. После исправления токена/прав бота перезапустите контейнер; недоставленные сообщения повторятся. Ёмкость очереди и число повторов ограничены, старые отчёты не выдаются за новые.
- Если компьютер выключен или полностью потерял интернет, он не может прислать уведомление о собственном отключении. Для отдельного контроля пропавших устройств нужен центральный режим, который остаётся в README как дополнительный вариант.
- Программа использует `sendMessage`, не запускает конкурирующий опрос `getUpdates`. [Telegram Bot API](https://core.telegram.org/bots/api#sendmessage).

Нативный Windows-запуск без WSL2 не предусмотрен. Контейнерный запуск проверен на macOS; отдельный прогон на Windows не выполнялся.
