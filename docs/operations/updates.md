# Обновления LiteChecker

Обновления программы и обновления подписки — разные вещи. Подписка заново
загружается перед каждым циклом проверок. На macOS и Linux установщик настраивает
почасовой поиск новой версии через системный планировщик. В Windows поиск
выполняется раз в час, пока работает мониторинг. Для этого установочный пакет
содержит платформенный `update-channel.json` с адресом публикации и доверенным публичным ключом.
Без него автообновление не настроено: это видно в статусе.

## Какая версия работает

Меню macOS/Linux показывает версию своего загруженного кода, а результат
ручного обновления — номер установленной версии. Старый установочный ZIP
может открывать уже обновлённую программу; его номер не определяет активный релиз.
После обновления заново откройте меню, чтобы оно тоже переключилось на новый код.

В отчётах проверок Windows, macOS и Linux версия агента указана рядом с ID:
`ID: device-… · v0.6.3`. Она сохраняется вместе с результатом проверки, поэтому
отложенная доставка не меняет номер версии. `v?` означает, что версия неизвестна
(например, в сохранённом отчёте старого агента); номер текущего меню не подставляется.

Для отдельного центрального HTTP-коллектора сначала обновите коллектор, затем
агенты: новые отчёты содержат необязательное поле `app_version`, а старые
коллекторы отклоняют неизвестные поля. Обычных клиентских установок с прямой
отправкой в Telegram это ограничение не касается. Новая версия коллектора
принимает старые отчёты и распознаёт их повторную доставку.

## Windows — обычная сборка

Откройте `LiteChecker.bat` и выберите «Проверить обновление». Если проверки
остановлены, обновление не запустит их. Пока мониторинг работает, версия
проверяется автоматически раз в час. После остановки мониторинга автоматический
поиск тоже прекращается. Выбор «Запустить» сохраняется: после входа в Windows
проверки и почасовой поиск обновлений возобновляются. «Остановить» отключает
возобновление. При переходе со старой версии один раз откройте новое меню и
запустите проверки; уже работающий процесс новое меню не дублирует.

Настройки и отчёты лежат рядом с запуском, в `_app/windows-state`.
Подписанный код обновляется отдельно, в `_app/.updates/releases`.
Закрытие меню не останавливает мониторинг: используйте пункт «Остановить».
Если файл старой версии ещё занят Windows, его удаление откладывается до
следующей очистки. Настройки, базовая установка и посторонние файлы не удаляются.

Ярлык автозагрузки указывает на постоянную базовую точку входа, которая выбирает
активную версию. Он не ссылается на удаляемые каталоги `.updates/releases`.
У macOS состояние запуска сохраняется пользовательским LaunchAgent: ручная
остановка отключает его загрузку при входе и не отменяется обновлением.

При следующем открытии меню используется активная проверенная версия. Уже
открытое меню может продолжать работать на предыдущей версии: её файлы сохраняются
до закрытия, даже если за это время вышло несколько обновлений. Настройки и отчёты
остаются в исходной папке установки. Работающий Windows supervisor сохраняет
базовый протокол управления до остановки; обновляются worker и новое меню.

## macOS и Linux

Первый раз распакуйте клиентский ZIP для своей ОС и откройте `INSTALL.command`
на macOS или выполните `bash INSTALL.sh` на Linux. Подписку, токен бота, ID чата
и необязательный прокси введите в мастере на устройстве. Публичные установочные
архивы и обновления не содержат секретов. Обновление сохраняет ваш токен,
прокси, подписку, настройки, ID устройства и очередь отчётов.

Для обычного управления повторно откройте тот же файл запуска. Дополнительные
команды выполняйте из постоянной папки программы: на macOS это
`~/Library/Application Support/LiteChecker`, на Linux — папка распакованного ZIP.

```bash
bash scripts/update.sh status
bash scripts/update.sh check
bash scripts/update.sh disable
bash scripts/update.sh enable
bash scripts/update.sh cleanup
```

`check` проверяет наличие подписанной версии сейчас; `cleanup` запускает
безопасную очистку вручную. Обычные `bash run.sh start` и `bash run.sh stop`
управляют именно проверками. Обновлятор не должен запускать остановленный
пользователем чекер. Чтобы прекратить и поиск новых версий, дополнительно
отключите обновления командой `disable`.

macOS: программа находится в `~/Library/Application Support/LiteChecker`,
проверку обновлений запускает launchd при входе и раз в час.
Linux: обновлятор работает на хосте, а чекер — в Docker. Нужны доступный
Docker Compose и пользовательский systemd. Установщик отдельно сообщит,
если планировщик недоступен; ручная проверка не означает работающий автозапуск.

## Что происходит при обновлении

1. Метаданные проверяются цифровой подписью Ed25519 с закреплённым ключом.
2. Архив проверяется по размеру, SHA-256 и списку файлов. Пути наружу,
   символические ссылки, секреты и некорректные архивы отклоняются.
3. Новая версия готовится отдельно. Переключение ждёт окончания текущего
   цикла, включая сохранение отчёта.
4. Проверяется локальная работоспособность программы. Сбой VPN-сервера
   сам по себе не является поводом откатывать программу.
5. При ошибке активации выполняется возврат к предыдущей версии.

Загрузки обновлений используют обычный системный маршрут и не подменяют
DIRECT-маршрут измерений. Если GitHub недоступен, установленная версия
продолжает работать; успешное обновление не выдумывается.

## Что очищается

- Среди управляемых релизов остаются текущая и одна предыдущая версия.
- Временные файлы неудачной загрузки удаляются сразу; забытые управляемые
  временные каталоги — после суток.
- Неизвестные каталоги, исходная базовая установка, настройки и `state/`
  не удаляются. В частности, папки и архивы в Downloads автоматически
  не чистятся: там могут лежать пользовательские файлы.

Доверенный ключ не заменяется ключом из скачанного релиза. Новая публикация
должна иметь больший номер последовательности; повреждённая или повторно
подсунутая старая версия не должна становиться обновлением.

Инструкция владельцу проекта: [выпуск подписанных обновлений](../development/releases.md).
Первая установка не нотарифицирована Apple: цифровая подпись обновлений
не является Developer ID и не снимает предупреждение Gatekeeper.
